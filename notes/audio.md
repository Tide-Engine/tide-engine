# Audio

## Inside another program (2026-10-22)

An embedded game (`tide/embed.h`, Unity) now hands its frames' audio to the
mixer as a window does, and the other program renders it on its own audio
thread through `tide_embed_audio`, which is `tide_audio_out_fill` (it says
`tide_mixer_rendered_elsewhere(true)`, so a reload's forget waits for that
thread; NULL with 0 frames says the thread stopped). Its microphone comes in
through `tide_embed_microphone` (`tide_audio_in_push`) while
`tide_embed_status.microphone` says a frame names a microphone voice. On the
web the page's program opens its own AudioWorklet at its first audio frame.
The mixer itself didn't change: the pinned mix is the same. `embed_audio` in
`tide_platform_embed` covers it; Unity's side is in `notes/unity.md`, Audio and
the editor's workflow.

## The listener alone includes tide/audio.h (2026-10-22)

A game that called `Audio.SetListener` or `Audio.SetFalloff` before declaring
any clip or `Sound` got a generated header that named `tide_audio_frame` (its
local state's audio list, behind `uses_audio`) without including
`tide/audio.h`, which only followed clips, named sounds and the microphone: a
C error in the game's header, found while building a prototype. `codegen.c`
now includes it whenever `uses_audio` is set too. `compiler/tests/e2e/audio_listener_only`
places the listener with nothing to play, checks `TIDE_HAS_AUDIO`, and runs.

## Optional Opus voice package (2026-10-22)

`packages/voice` now adds session voice over the existing microphone and
audio effects. A muted microphone effect copies bounded blocks to the frame
thread for Opus; receive effects read decoded PCM queues. No mixer/capture
backend, clip layout or generated audio API changed. Merely listing the
package opens no device. Contracts, buffering, ownership and validation are
in `notes/voice-package.md`; older "voice chat not built" entries below
describe the pre-package implementation.

Scalar Clip values without assets (2026-10-19) now request their existing C
definition even when no Sound, microphone or clip asset is declared. The
checker distinguishes using a Clip type/value from enabling playback; unused
built-in Sound fields do neither. clip_values and independent header cases in
the asset-usage unit target cover this omission, with no asset/audio feature
macros or match-state change. Contracts and full validation: notes/language.md.

Clip asset collection helpers (2026-10-18) take read-only List<Clip> or
Map<string, Clip> parameters in synchronous CPU functions/methods. Passing
copies no collection and creates no voice or decoded-clip ownership; only
Audio.Play retains its existing playback behavior. Collections cannot escape
or wait, while selected Clip values retain ordinary local value semantics.
`asset_borrows` covers playback and pack reload; notes/language.md records
contracts, diagnostics and full validation. No audio runtime API changed.

## Forget completion ordering (2026-10-18)

Build run `39128917687` failed Android's `tide_platform_audio_device` only at
the assertion that no large effect states remain after `tide_mixer_forget`.
`apply_handed` published `forget_done` before `settled`: the waiting frame
thread could observe completion, reclaim against the previous settled serial
and return with retired states still allocated. Direct forget frames now
publish their settled serial before acknowledging completion. The acquire on
the waiter then observes everything needed for reclamation. Replacement normal
frames retain their existing rule: their new states settle after rendering.
No API, mixer output, allocation policy or wait limit changed.

`tide_platform_audio_forget` instruments only its own compiled copy of the
mixer and resumes the waiter's reclamation immediately after the actual
completion store. It checks a rendered voice's and bus's 200 KB states are
already reclaimable. This deterministically fails with the old mixer and
passes with the corrected ordering, without a device or scheduler-dependent
stress loop. The production mixer has no test hook. Full-suite validation is
recorded in `notes/releases-and-ci.md`.

## Rendering and platform

- **Reading `Sound` defaults needs no stored sound** (2026-10-09): `Audio.SetVolume(Sound { }.bus, volume)` gives master bus 0 with the game's exact `[Bus]` enum type when one is declared, or an int otherwise. Packages can therefore apply a master level without declaring or naming the game's buses. `gen_sounds` writes `tide_sound_voice` as `TIDE_HELPER`, as its other optional helpers are, so a game that only reads a `Sound` literal does not fail strict C builds with an unused static function. The audio list still resets bus volumes to 1 each frame. `compiler/tests/e2e/audio` checks default volume, quarter volume applied across resets, mute, no extra voices and a host with no audio list while keeping no `Sound` fields; `buses` checks the same default-bus expression with a game's enum beside its music and effects levels.
- **Audio is planned, and its eight cards are built** (2026-10-07; the design is `docs/spec.md`, Audio, with what's agreed and what's Claude's picks, and `docs/game/audio.md` is the users' page; the Tide side is whole but for what's listed as not built, a window plays through the system's device on every platform, clips import WAV, Ogg Vorbis, MP3 or FLAC, and the microphone is a clip). Audio is presentation, never the match: it reads the world and writes nothing to it, and the simulation never includes an audio header. What's built, and what code relies on:
  - **`tide/audio.h` is the frame's audio, as `tide/draw.h` is its drawing** (`engine/src/audio.c`): a `tide_audio_frame` records one-shots (`tide_audio_play`, `tide_audio_play_at`), voices named by an id (`tide_audio_voice`: clip, position, volume, pitch, loop, playing, bus, effect and its knobs, copied in), the listener, a falloff and each bus's volume and effect. `tide_audio_reset` empties it for a frame with every bus at 1 and nothing said, as `tide_draw_reset` does; every frame starts from the defaults. A `tide_clip` is interleaved float samples of any rate and 1 or 2 channels, which stay where they are while a voice plays them: the mixer reads them on its thread and copies nothing. A `tide_audio_effect` is code the audio thread runs once a block (`tide_audio_effect_fn(samples, state, knobs)`: 512 interleaved floats, the voice's own state of up to a megabyte, a copy of the frame's knobs of up to 256 bytes: `TIDE_AUDIO_STATE_BYTES`, `TIDE_AUDIO_KNOBS_BYTES`), named by an id whose change starts the state over; on a voice with no clip it's a source. The host records nothing into it yet: `tide_run_audio` in `tide/host.h` is reset each frame and handed over after the draw (`tide_platform_audio`), for the Tide side to fill when it comes.
  - **The mixer is `platform/src/mixer.c`**, stereo at 48 kHz in blocks of 256 frames (`TIDE_AUDIO_RATE`, `TIDE_AUDIO_BLOCK`, `TIDE_AUDIO_SAMPLES`), in floats, with nothing of a clock's: `tide_mixer_submit` (the frame's thread) copies a frame into one of three buffers and publishes it with one atomic exchange, and the renderer takes the newest at its next block (`tide_mixer_take`, from `tide_mixer_render`), so neither thread waits for the other; one-shots go through a ring of 1,024 (`TIDE_MIXER_ONE_SHOTS`), so none is lost between two blocks, and past it they're dropped and counted (`tide_mixer_dropped`). The renderer allocates nothing and blocks on nothing: 256 voice slots (`TIDE_MIXER_VOICES`, a new one past that taking the quietest's), each with its own knobs bytes and 4,096 of state (a bigger state is memory the frame's thread makes for it: A state can be big, below). `tide_mixer_render(out, frames)` renders any count by whole blocks, carrying the remainder, so any sizes give the same samples; `tide_mixer_flush` drops the remainder. What a block does: each voice's clip read at its own rate and pitch by linear interpolation (a double cursor), its effect, its gains ramped linearly over the block from the last block's (volume, and for a spatial voice equal-power pan by the listener's right and `near / distance` falloff scaled to 0 at `far`; defaults 1 and 50), into its bus; each bus's effect and ramped volume into the master; the master's out. A voice not named by a frame, or named with `playing` false, fades out over a block and goes; `playing` false then true, or another clip, starts the clip over; a named voice whose clip ended stays silent until then; a one-shot ends with its clip. A frame's `forget` stops everything at once and drops every effect, for a reload. Every float operation is a basic one (`__builtin_sqrtf` for the pan), so the mix is the same bytes on every platform: `tide_platform_audio` pins a hash of a scene of everything, the same natively and under Node.
  - **A headless run has audio with no device**: after each frame's function, the platform renders 800 frames (a 60th of a second) into a buffer that holds what a capture can still ask for and no more (`headless_audio_frame` in `platform/src/platform.c`: the whole run with `--capture-audio`, what played since the last `capture-audio` line while the script has another, `tide_script_captures_audio`, and otherwise a frame, so a long run that captures nothing stays flat; it grew by 12.5 MB a 30 seconds before 2026-10-07), `--capture-audio <file.wav>` (`tide_headless_desc.capture_audio`, `tide_run_configure`) writes the whole run as the run ends, and a script's `capture-audio <file.wav>` line (`EVENT_CAPTURE_AUDIO` in `platform/src/script.c`, `tide_platform_capture_audio`) writes what played since the last such line. The WAV writer is `platform/src/wav.c` (16-bit stereo PCM, samples clamped and rounded to the nearest, ties away from zero; `tide_wav_header` reads one back, for tests). A window with a device gets nothing from `tide_platform_audio` yet: the mixer is submitted frames and nothing renders them until the backends come (WASAPI, CoreAudio, ALSA at run time, AAudio, an `AudioWorklet`), each a device callback that calls `tide_mixer_render`.
  - **`Clip` and `Audio.Play` are the Tide side** (card 2). `Clip` is `TY_CLIP` (`tide_clip_ref`, 8 bytes: the name the pack's loader gives a declaration's sound, as a `Texture` of the pack's names its image; `tide_pack_clip_of`, `tide_pack_clip_find` in `engine/src/pack_load.c`, kinds `TIDE_PACK_CLIP` and `TIDE_PACK_CLIPS`, laid out after the region as textures are), an asset kind (`ASSET_CLIP`: `asset_files.c` decodes the file to check it, with the engine's own WAV reader, `tide/wav.h`, which tidec compiles too), and a resource of this machine's wherever a `Texture` is one (`holds_render_resource`, `element_ok` for an asset's glob only, the layout table in `codegen.c`). `tide_clip_of(ref)` (`engine/src/audio.c`) finds the file's bytes in the loaded pack and decodes them once, by what's in them, into a cache of the engine's own that `tide_clips_free` empties: so a voice never plays samples of a pack that's gone (a repack keeps the old file's beside the new), and a library's unload frees them after the host had the mixer forget (`tide_platform_audio_forget` before `old->unload()` in `platform/src/reload.c`: a reload stops every sound). `Audio` is a builtin owner (`builtins.c`: three `Play` signatures, plain, at a `float2`, at a `float3`, with volume and pitch defaults that codegen fills in as `1.0f`), its call `CALL_AUDIO`, checked by `check_audio_use` (views, local handlers, functions; the match, the input, tasks, methods and GPU code refused) and `check_audio_calls` (a function that plays is local code's to call, as `Frame.dt`'s is), and generated as `c_callee(tide_l->tide_audio, tide_clip_of(clip), ...)`: a function that plays takes the local state (`takes_local`), the local state has the frame's audio list when the game plays (`program.uses_audio`: `TIDE_HAS_AUDIO`, `tide_local.tide_audio`, `tide_local_audio`, which `tide_host_game.audio` is and the host calls before each frame). A game that plays nothing and has no `Clip` asset generates the C it did, byte for byte (old and new tidec over every game's source list, with `--layout` and without: 248 games the same, and the two that play, the e2e test and the capture game, only compile with the new one).
  - **`Sound` fields and the listener are card 3.** `Sound` is a built-in struct (`prog->sound` in `check.c`'s `add_builtins`, beside `Shape`; `named_only`, so it's in generated C, its blend helper and the layout only for a game that names it, which also sets `program.uses_audio`). The frame names every `Sound` of local state that plays: `gen_sounds` (`codegen.c`) writes `tide_local_sounds`, which walks local singletons, local archetypes' rows and the attached local parts of match components (the walk `gen_rebind_resources` makes, for `sound_fields`), structs in them too, and records each playing one as a `tide_voice` (`tide_sound_voice`: its clip through `tide_clip_of`) named by its field's path hashed and, for a row, the entity's bits (`tide_sound_entity`); `tide_frame` calls it last, after the local commands applied. `Audio.SetListener` (a `float3` and a quaternion, or a `float2`) and `Audio.SetFalloff` are `Audio`'s other signatures, through `CALL_AUDIO` like `Play` (whose default-filling in `gen_builtin_call` is by name, `Play` alone). Generated C for a game that names no `Sound` is byte for byte what it was (old and new tidec over every game's source list, with `--layout` and without: 252 games the same, and the `sound` e2e test only compiles with the new one).
  - **Buses and `audio` declarations are cards 4 and 5.** `[Bus]` marks the game's enum of buses (`prog->bus_enum`, found right after `collect_decls` so `Sound.bus` resolves as it, checked in `check_attributes`); `Audio.SetVolume` and `Audio.SetEffect` are checked by hand (`check_audio_volume`, `check_audio_bus_effect`: the bus as the enum, or a number with none) and generated with a `(uint32_t)` cast. An `audio` declaration is a `DECL_FUNCTION` with `is_audio` (`parse_audio`; `check_audio_signature` sorts its parameters into `audio_state` and `audio_knobs`; `check_audio_bodies` refuses what the audio thread can't do, after the call-site passes, with `makes_text` noted per function in `check_expr` and propagated through calls); a call of one is `CALL_EFFECT`, an `Effect` value (`check_effect_value`), generated as `tide_effect_<Name>(knobs)`. `gen_effects` (in `gen_sounds`) writes each declaration's wrapper `tide_audio_fn_<Name>` (the block, state and knobs cast, with `0u` for each `mut` parameter's `where`), the `tide_effects` table by id and `tide_effect_of`, which the voice walk and `tide_audio_set_bus_effect_value` resolve an `Effect` with; `TIDE_AUDIO_KNOBS_BYTES` is 256, what an `Effect` holds. **Three built-in structs are in generated C only for a game that names them** (`builtin_struct_unnamed`: `Sound`, `Samples`, `Effect`), and so are the arrays only their fields made (`array_unwritten`, with `order_arrays` numbering them after the game's own); naming `Sound` names `Effect`, and `program.quiet_names` keeps a built-in struct's own field resolution from counting as the game naming anything. Old and new tidec over every game's source list, with `--layout` and without: every game that plays no sound the same, byte for byte.
  - **An `audio` declaration's state and knobs have a size, which is an error past it** (2026-10-08; part of what No Tide code can corrupt memory rests on: see Language). Until then a state was the 4,096 bytes every voice had, the generated wrapper cast them to the game's struct and `engine/src/audio.c` only clamped `state_size`, so a state with an `int[4096]` in it (16 KiB) was written into the next voice's slot, and knobs over 256 bytes were a `_Static_assert` of generated C's, an error with none of tidec's words. What's built, and what code relies on:
    - `check_audio_sizes` (`compiler/src/check.c`, right after `check_audio_bodies`, so once every call is known) is an error at the state parameter for a struct over `TIDE_AUDIO_STATE_BYTES` (1,048,576 since big states, below: "an audio declaration's state is 1048576 bytes at the most, and 'Tail' is 1048580") and at the knobs parameter for one over `TIDE_AUDIO_KNOBS_BYTES` (256), each with a note that says to make the struct smaller. A declaration that rolls (`decl.rolls`, which is why the check comes after `check_roll_calls`) has a `Random`'s 8 bytes less, as its wrapper keeps its generator after its state: the error says "where it rolls with Random", and its note where it rolls. check.c reads both numbers from `tide/audio.h`, so a limit that changes there changes the error.
    - **A type's size is `types.h`'s, for the checker and codegen alike**: `type_layout`, `decl_layout` and `decl_layout_padded` are in `compiler/src/types.c` (they were codegen's own), and codegen's `field_padding` gets the padding it writes out from there. A type whose bytes change changes them there, once. Moving it changed no game's generated C (old and new tidec over every game's source list, with `--layout` and without: 225 games).
    - **A size that's more than an int says is `LAYOUT_MOST`** (`saturated` in `types.c`), never what the int wraps to: structs of arrays of structs say gigabytes in a few lines, four of them wrapped to 0, and 0 fits anything. The error then says "over 2147483647". Sizes under that are what they were.

  - **A state can be big: an echo's or a reverb's delay line** (2026-10-08. The owner: "i do want echo or reverb to be a future feature so maybe we prepare now", then, asked, that a long delay line is written as a longer array in the state, and that it's built now. What's built, and what code relies on:
    - **`TIDE_AUDIO_STATE_BYTES` is 1,048,576**, the most a state takes (2.7 seconds of stereo), and `TIDE_AUDIO_STATE_SMALL` 4,096, what a voice and a bus keep in themselves, as every state was (`tide/audio.h`). The frame records no effect for one that says more than the most (`copy_knobs` in `engine/src/audio.c`, which clamped it: its code would write past what it's given).
    - **A state over `TIDE_AUDIO_STATE_SMALL` is memory of its own, which the frame's thread makes and frees** (`big_state`, `state_for`, `free_settled` in `platform/src/mixer.c`), as the renderer allocates nothing. `tide_mixer_submit` keeps one for each voice id (or bus) and effect (id and size) its frames play, zeros as it's made, and hands it with every frame that plays it (`handed.states`, beside `handed.voices`, and `bus_state`); a voice's slot points at it (`voice.big`, `bus.big`), and the effect runs in it. With no state to run in, an effect isn't run: a one-shot's, which has none.
    - **The frame's thread decides when a big state starts over**: a frame that doesn't play the voice (not named, or `playing` false), or that gives it another effect, lets the state go, and the next that plays it gets another, zeros. The renderer goes by which state it's handed (`update_voice`: another one is the effect started over; a voice that stops keeps the one it had through its fade). So where two frames come between two blocks and the first doesn't play the voice, a big state starts over though the renderer never saw the voice stop, where a small one, which is its slot's, goes on. A stolen slot's voice gets its state back in its next slot.
    - **Freeing waits for the renderer, with no lock and nothing timed.** A frame has a serial (`handed.serial`); the renderer says the last frame it applied and rendered a block after (`m.settled`, stored at the end of `render_block`, and as a forget is applied): by then every voice that frame stopped has faded and gone, and every other has that frame's states. A state retired at frame S (the first that doesn't hand it) is freed at the first submit that finds `settled` at S or past it. **A state the renderer never had is freed at once**: publishing a frame gets back what was pending, which says whether the renderer took the frame before (`PENDING_NEW` still set: it didn't, and now can't), so each state knows whether any frame the renderer took handed it (`seen`). So a machine with no device, where `tide_platform_audio` submits and nothing renders, holds what plays and nothing more, and a device that stalled holds at most what it had as it stalled. `tide_mixer_forget` frees everything once the forget is applied. `tide_mixer_states()` counts them, for tests.

## Audio asset imports (2026-10-10)

- `compiler/src/audio_files.c/.h` is the compiler's content-based Clip validator and importer. `audio_file_read` leaves valid RIFF WAV and Ogg Vorbis unchanged, or returns an owned mono/stereo IEEE float32 WAV for MP3 and native FLAC. The converted WAV has an 18-byte format chunk, a fact chunk with its frame count, and little-endian float samples; there is no PCM16 quantization or rate conversion. `asset_files.c` caches conversion separately from the original file bytes and clears both on file invalidation. A `List<byte>` asset of the same file therefore still reads MP3/FLAC bytes, while the Clip pack entry receives the WAV. Lists, maps, aliases and kept Clip references use the existing asset and pack paths.
- The tool-only `tide_audio_import` library builds unchanged `dr_mp3` 0.7.4 and `dr_flac` 0.13.4 from dr_libs revision `dfe8377631000664666519fdb83da193fd8037f4`, retained under `compiler/third_party/dr_libs` with its upstream license and pin. The wrapper disables SIMD and filesystem APIs, MPEG Layers I/II and Ogg FLAC. FLAC frame checksums remain enabled. The compiler's float flags also apply to the vendor build. Imported formats add no runtime codec dependency and do not change `Clip`, `tide_clip`, the mixer or Vorbis streaming. The existing runtime's own WAV/Vorbis decoders and the WAV/Vorbis-only `--microphone` input remain as described above; MP3 and FLAC are build-time Clip imports only. The earlier card notes describing the asset checker as WAV/Vorbis-only are superseded here.
- MP3 imports accept MPEG-1/2/2.5 Layer III at ordinary CBR/VBR bitrates, mono/stereo, ID3v2, ID3v1 and APE tags, and Xing/Info encoder delay/padding. A strict frame-boundary scan rejects cut tags/frames, invalid or changing headers and free-format bitrates. The decoder's output count must match the complete frames after metadata and gapless trimming. Native FLAC imports require mono/stereo and a nonzero declared STREAMINFO sample count, then decode the complete file and require exactly that count; truncated or checksum-skipped frames are errors. Unknown-length streaming FLAC, Ogg FLAC, AIFF/AIFC, Ogg Opus, AAC/M4A, surround sound, free-format MP3 and runtime byte-to-Clip decoding are not added.
- MP3/FLAC source bytes are bounded at 128 MiB; imported PCM at 256 MiB and 30 minutes at its source rate. A bounded decoder allocator permits at most 32 MiB of aggregate vendor allocations. Declared FLAC counts and scanned MP3 durations are checked before PCM allocation; decoded output grows in bounded blocks and every sample must be finite. Imports become whole-decoded WAVs at runtime, so long imported music uses more pack space and RAM than a retained streaming Vorbis file. Export long music as Ogg Vorbis when compressed runtime streaming is needed.
- Clip errors now name the recognized format and reason: WAV codec tag, channels, depth, bad alignment, short chunks or partial sample frames; Ogg/Vorbis's existing detailed reasons; MP3 tags/frames; FLAC metadata/count/checksum; and identified unsupported Opus, AIFF, RIFX/RF64 containers. WAV import validation also checks the RIFF bound, the complete PCM/float extensible GUID, valid bits not exceeding width, finite float samples and float64 values fitting playback float32. Valid bits zero continue to mean the full stored width; valid bits below width retain WAV's left-aligned sample interpretation. This validation does not add new WAV codecs to the runtime.
- Ogg CRC-32's lookup table in `engine/src/vorbis.c` is now immutable. The previous lazy table wrote `table[1]` before the rest of its entries and let simultaneous first-use Clip preparation race on mutable storage, potentially rejecting valid checksums. Existing reference decodes and corrupt-page checksum tests cover the constant values; removing initialization eliminates the first-use race.
- Tests: `tidec_audio_files` checks exact 24-bit FLAC samples through float32 WAV, independent FFmpeg references and gapless lengths for stereo CBR and mono VBR MP3, truncated tags/frames, FLAC checksum damage and declared-length bounds, detailed WAV failures and identified unsupported containers. `compiler/tests/e2e/asset_audio_formats` checks the resulting pack on native and web, preserved raw MP3/FLAC byte assets, list/map playback, alias sharing, exact FLAC samples and kept clips across pack replacement. `asset_clip_mp3_truncated`, `asset_clip_flac_truncated`, `asset_clip_wav_codec`, `asset_clip_opus` and the existing bad-WAV/Ogg programs pin their compiler diagnostics. The synthetic fixture sources, encoder commands and independent reference descriptions are in `compiler/tests/e2e/audio_import/README.md`.
- The audio unit target also pins conversion cache invalidation: editing MP3 encoder padding changes its decoded length by one frame without changing source size or mtime; the old conversion stays until `asset_files_changed`, then refreshes, while a byte asset reads the edited compressed bytes. Focused native asset/import/diagnostic checks passed 84/84. An isolated Linux clang 18 ASan/UBSan/leak run passed the six decoder unit cases and 36,200 exact-allocation inputs: every MP3/FLAC fixture prefix, bounded header/payload corruption and randomized format-prefixed short inputs. The cache case requires full compiler integration and is exercised by the native unit target.
- **Vorbis decode limits** (2026-10-26, from fuzzing; `notes/memory-safety.md`, Remote assets). `tide_vorbis_open` walks every packet's framing (mode, previous and next window flags) through the helper the reader uses (`read_framing`, `framing_frames`) and records `tide_vorbis_frames_given`: exactly what a reader yields, the granule or fewer where the packets give fewer. `decode_clip` sizes a whole decode by that, never by the granule (which once made a 2.9 KB file ask for 8 GiB, wrapping on wasm32 into a write past the buffer). A clip is whole only within `tide_clips_whole_seconds` at a rate capped by `TIDE_CLIP_WHOLE_MAX_RATE` (384 kHz) and within `TIDE_CLIP_WHOLE_MAX_SAMPLES` (2^27, frames times channels in 64 bits); past either it streams, the same samples, and its read loop asks only for the frames left. Streamed clips report frames given. `tide_vorbis_decode` uses the same count and refuses output past `TIDE_SOUND_MAX_SAMPLES` (`tide/wav.h`, 2^30, shared with WAV and tidec; exactly 2^30 is refused too, as 4 GiB of floats wraps the web's `size_t`). Limits in `tide/vorbis.h`, refused at open before what they ask for is made: `TIDE_VORBIS_MAX_ENTRIES` (2^20 codebook entries a file; libvorbis writes at most 11,241), `TIDE_VORBIS_MAX_VALUES` (2^22 vector values; about 61,000) and `TIDE_VORBIS_MAX_WORK_PER_FRAME` (16 block samples a frame given, plus two long blocks; real files 2 to 2.5). The floor's inverse-dB table is a constant, as the CRC table is: its lazy fill raced between the preparation pool and the audio thread. Ogg page and packet arithmetic uses `size - at` and refuses a file too big rather than wrapping. Tests: `vorbis_decodes_the_same_bits` (hashes of the three reference decodes, which nothing pinned before; CI confirms them on other platforms and the web), `vorbis_refuses_codebooks_past_the_limits`, `vorbis_decode_sizes_by_its_packets_not_its_word`, and `audio_prepare_sizes_a_vorbis_clip_by_its_packets_not_its_word` in `tests/test_audio.c` (whole and streamed, a granule of 2^31 at the largest rate, a 255-channel copy refused).
- **tidec decodes an Ogg Vorbis clip once at build** (2026-10-26), as MP3 and FLAC are, in 4096-frame blocks keeping no samples (`check_vorbis`, `compiler/src/audio_files.c`), and refuses a non-finite sample and a packet skipped or ending inside its floors or residue (`tide_vorbis_reader_damaged`).
