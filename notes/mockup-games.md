# mockup.games: local service and Tide previews

## Scope and product decisions

The owner bought `mockup.games` for a service that turns anyone's game idea into a small playable game. The default target is polished presentation and a complete small loop; a quick mode can prioritize mechanics. Users can supply visual references or assets. Projects are collaborative: friends can discuss, edit the brief, playtest, leave feedback and request concurrent iterations.

A game's design determines its player count. Social playtesting is a separate layer: single-player games can still have spectators and shared control. Taking the controller is immediate, without an approval request. The current implementation runs one simulation in a host browser and streams its canvas to teammates; control handoffs retain that running simulation.

The service starts in `mockup/` in this repository, with its own package and application boundary, so it can later be extracted. It is independent of the older, on-hold mod build service under `builds/`; nothing there is deployed or reactivated by this work.

## What is built

- `index.mjs` starts the authenticated application and the isolated preview origin on separate ports. The application defaults to `127.0.0.1:4173`, previews to `127.0.0.1:4174`. It verifies the prepared starter's source and artifact hashes at startup. Missing starter output is reported as unavailable rather than replaced with a pretend game.
- `server/app.mjs` owns local email/password accounts, scrypt password hashes, hashed cookie sessions, membership, invitations, messages, feedback, original uploads, jobs, revisions, playtest rooms and owner administration. Membership checks protect project data, downloads, preview tickets and signaling. Browser writes validate their origin. `server/store.mjs` serializes mutations and atomically replaces `.data/store.json`; it assumes one service process per data directory.
- The project brief is an actual Yjs text document. Concurrent updates merge and persist. Server-sent events carry project updates, cursors and typing/editing presence. `scripts/bundle.mjs` bundles the pinned Yjs browser dependency into `client/vendor/yjs.js`.
- `client/room.js` and `public/bridge.js` connect the social playtest. One host's real Tide canvas supplies WebRTC video; spectators receive that stream rather than running independent copies. Authenticated controller events reach the host's preview bridge. Handoffs change the controller epoch and release held inputs, so stale controller events are rejected. The spectator stream has no audio track.
- Responsive client layouts support phones. Moonwake has a visible drag joystick, a generous dash control, simultaneous move/dash touches and a touch/mouse replant button. Preview input coordinates are normalized for forwarding between different screen sizes.
- `runtime/pipeline.mjs` optionally calls the Responses API with structured output, current working source, the shared idea, recent conversation, feedback and uploaded assets. Selected image references and the latest captured screenshot are actual image inputs. Generated source is built with an installed Tide package using `tide build <folder> --web --release -o <folder>/build/game.html`. Failed compilation can trigger two repairs, for at most three builds. Usage and elapsed build time are recorded for failed attempts as well as successful ones. Without the API key/toolchain, generation is disabled explicitly.
- Generated source is limited to root-level `.tide` files, with no native interop, packages or remote URLs. `runtime/assets.mjs` conservatively scans asset declarations and permits only exact, unescaped uploaded game-asset literals. No path expressions, globs or traversal are accepted. Direct build formats are PNG/PSD, WAV/Ogg and self-contained GLB; GLB URI/chunk validation rejects external resources, including escaped or duplicate JSON URI keys. Only referenced game assets are copied into each work folder. Upload originals stay untouched in the shared library.
- Revisions retain source, polish mode and separate HTML artifacts under their own IDs. A job built from the still-active revision can become active; a job whose base became stale remains a candidate and does not change the shared polish setting. Accepting a version compares the expected active revision to avoid overwriting a teammate's intervening choice and applies that version's polish setting. Failed jobs preserve the existing playable version. A service restart marks interrupted jobs failed rather than leaving them indefinitely queued.
- Feedback captures the played revision, a screenshot when available, recent controller inputs, viewport data and available browser diagnostics. The stored capture explicitly has `worldSnapshot: null`. No browser replay or world export is claimed.
- `scripts/admin.mjs` provisions an owner account offline, prompting for a hidden password. Run it with the service stopped because the store has one writer. `MOCKUP_ADMIN_EMAILS` can narrow access to provisioned admins; listing an email does not itself grant privileges. Administration is read-only and can inspect all projects and their members, global account count, the latest 100 jobs, provider usage and service counters.

## What the code relies on

- Node 24.16 or newer, especially on Windows: earlier versions have the networking crash described in `notes/testing.md`. Browser runners use muted headless Chrome/Edge. `TIDE_HIDDEN=1` is set for spawned Tide tooling, and native starter checks use their own built executable without showing a window.
- An installed Tide package supplies the compiler, headers, engine sources and WebAssembly runtime libraries. `TIDE_BIN` overrides discovery. The first verified installation was `tide 0.3.0-nightly.112`, with LLVM 23.1.2. Source changes require regenerating the starter manifest before service startup.
- Application and preview origins remain distinct. Preview tickets are scoped to an authorized revision, previews have restricted CSP, and the bridge checks both message origin and parent window. Public hosting needs these origins preserved behind its proxy; port separation in local development is not a public worker sandbox.
- A connected browser owns the running simulation. Taking control only changes where input comes from. If that host leaves, a replacement host starts a new run; current world state is not migrated.
- Uploaded asset paths are relative to the declaring Tide file. Root-level source files and exact copied `assets/<id>/<name>` paths therefore change together. Other upload formats can remain library references; they are not silently converted into supported Tide assets.
- The provider's returned token usage is the accounting source. Cached input is a subset of total input. Estimated model cost requires valid configured rates for uncached input, cached input and output, stored with each request. Unknown rates remain unknown; infrastructure charges are excluded.
- Owner storage counters measure regular files with `lstat`: unique original asset blob paths, unique published HTML artifact paths and recursive `work/<jobId>` trees attributed through persisted project jobs, including failed attempts and compiler caches. Symlinks and Windows junctions are never followed. The global total deduplicates shared blob paths across projects; a project's own total includes every blob it references. Source arrays and feedback capture payloads count their actual serialized UTF-8 bytes in the JSON store, including base64 screenshot encoding. Shared account/project/job metadata, CRDT state, sessions and JSON field overhead are explicitly excluded. These are attributed project bytes, not allocated filesystem blocks or the entire data directory. Work/artifact copies occupy different paths and count separately. Build time is wall time, not CPU time. Runtime figures are current process RSS, JavaScript heap, uptime, active/queued jobs and account/project counts.
- `mockup/` has no direct engine runtime imports. Extraction must carry the optional documentation currently read from parent `docs/`, and move or replace the starter web test's parent `cmake/run_wasi.mjs` reference. `.data/`, `.env`, generated vendor files and starter caches are ignored and need separate migration if wanted.

## Moonwake starter and validation

`starter/game.tide` is a complete single-player seed-collection game: a floating midnight garden, four circular flower-bed obstacles, a responsive hooded courier, dash, trails/sparks, ambient flowers/fireflies, readable score/timer, completion and restart. It draws procedurally and requires no asset downloads or image generation.

`scripts/prepare-starter.mjs` builds a real self-contained WebAssembly HTML page and writes `starter/build/manifest.json` with source/artifact SHA-256 values and toolchain identity. Missing/failed tooling rejects preparation. `scripts/starter-test.c` and `scripts/test-starter.mjs` check sampled keyboard and simultaneous mobile move/dash input, touch replant, movement, dash, collecting each seed once, timer/completion, restart, world packing/restoration and 120 ticks of deterministic input replay. The same fixture runs natively and under WASI; the verified final hash on both was `6704842711661338406` on 2026-10-09. Desktop `1030×760` and compact `390×350` captures were visually inspected.

From `mockup/`, `npm run check` checks JavaScript syntax; `npm test` covers accounts/access control, persistence, preview-ticket scope, uploads, instant takeover/stale inputs, signaling, concurrent Yjs edits, revision/polish races, interrupted jobs, admin access, usage/cost accounting, compile repair and asset-path/GLB validation. Storage tests pin duplicate-blob accounting, failed-build work/cache bytes, serialized feedback captures and skipping a symlink (a junction on Windows) to unrelated files. A pipeline regression rejects a traversal asset before staging source or invoking the compiler while retaining the charged model response's usage. Provider/build responses in these unit tests are stand-ins. `npm run test:starter` builds and tests the real native and web game. `npm run test:browser` starts temporary isolated app/browser sessions and exercises signup, invitations, the actual game stream, remote control, named cursors, concurrent editing, captured feedback, phone layout and owner administration; it requires the prepared starter and Chrome/Edge, or `TIDE_BROWSER` pointing to one.

The service build adapter also compiled the starter's real source into a separately hashed web artifact. The browser suite verifies that spectators reconnect after the host restarts the preview. The starter's native/web checks and screenshot inspection do not verify a live paid provider request or a public deployment. Phone layouts are browser-emulated here; another physical device requires HTTPS and configured reachable application/preview origins.

## Not built

Billing, subscriptions, one-time free-game allowances, email verification/password recovery, public multi-tenant worker isolation, build memory/CPU/network limits and global quota accounting, automatic work/cache retention, browser world snapshots, replay, before/after scenario execution, state-preserving host migration, spectator audio, automatic setup of separate networked game instances for multiplayer designs and a managed TURN service are not built. The local source/asset checks do not replace isolated workers for public compilation. Work folders and compiler caches can grow until cleaned up by the operator.

No live provider end-to-end run, TURN configuration, `mockup.games` DNS/certificate setup or domain deployment is included. The older `builds/` service remains on hold.
