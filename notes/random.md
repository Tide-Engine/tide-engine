# Random numbers

## Match singleton seeding ignores local declarations (2026-10-18)

The CRACKED report was still current: moving a local singleton changed a
match singleton's default Random seeds. The global declaration ordinal also
entered the simulation identity, so a presentation-only edit changed both
behavior and compatibility. The initial audit's claim that these builds already
had the same simulation identity was incorrect; a direct two-build probe found
different identities as well as different seed sites.

Checking now assigns a separate `match_singleton_index` after synthetic storage
is complete, counting only match singletons. Generated default seeding and the
simulation graph use that ordinal for match singletons. Local storage keeps its
existing numbering and seeding; components, explicit Random(seed), runtime PCG
arithmetic, source-order rolls and field-path numbering are unchanged. Reordering
match declarations may still change their default streams. This adds no runtime
function, generated ABI or state-layout field.

`random_local_order` and `random_local_first` compile the same match with a local
singleton before/after it and an added attached local field before a second match
singleton. They share a pinned 30-tick hash, `5079178118440730783`, and check
explicit seeds and snapshot replay. Simulation-identity tests cover the same
presentation edits. A related identity defect found by those tests is recorded
in `notes/language.md`: compiler-generated discard names included source positions.
Validation: complete warning-free Windows debug builds exercised all 2,371
native CTests (68.15 s, including 31 Vulkan/OpenGL checks) and 2,282 WASI/web
CTests (210.32 s, including WebGL/WebGPU). Their only failures were the three
fixtures whose fresh default singleton streams intentionally changed. Native
and WASI printed identical replacements: the random fixture's match hash is
`f556fd146da75bc9`; churn ends with `alive 64 text 429 lists 366076 keys 566 big
40000`; Sumo's pins are `c659a401358bc369` / `3b39af7fab9a0826`. Those expectations
are updated. All six affected native checks and five web checks pass afterward,
including the two local-order layouts. The same checks pass in native release
and web release, confirming all four configurations share both new RNG pins and
Sumo's network pins. The release churn executable was explicitly built before
its final rerun. Existing runtime math/PCG, physics and other world pins remain
unchanged. The full simulation-identity/asset-usage unit target and production
docs build pass with clang 23.1.2 / checkout-local Node 24.19.0. Missing example
pages in the docs build are its existing placeholders. Runs used TIDE_HIDDEN and
muted browser runners. Other OSes, Android, sanitizers and private-prototype
playtests were not run; no CI or deployment was requested.

Build notes, moved here from `AGENTS.md` as they were: what's built, what code relies on, the tests and the measurements. `AGENTS.md` has the rules every session needs and the index of these files. The headings below are that file's sections as they were, and "see <Section>" names one of them: the index says which files each is in. What a note calls "below" or "above" may be in another of these files now: search `notes/` for its name.

## Language

- Random numbers (`docs/spec.md`, Random numbers: that `Random` rolls on the type with no state of the game's, and that rolling writes nothing, are the owner's, 2026-10-08; everything else is Provisional). What's built, and what code relies on:
  - **Rolls on the type: `Random.NextInt(6)`, and `Random.seed`** (built 2026-10-08; the owner found a generator of one's own inconvenient and `Time.seed` out of place, and picked calls on the type over a built-in singleton, which every rolling system would have had to write). What code relies on:
    - **A roll is `CALL_ROLL`** (`check_roll` in `compiler/src/check.c`, from `check_method` where the object names the built-in `Random`, `names_random`): the value's own signatures (owner `Random` in `builtins.c`), generated as the same `tide_random_*` function with `tide_dice`, a `tide_random *` every code that rolls has in scope. It counts as a call that writes (`writes` in `codegen.c`), so rolls keep their turn in an expression. So does a call of a function or method that rolls (`method->rolls` in `call_keeps_order`): without it, `Deeper(6) * 10 + Random.NextInt(6)` rolled in another order natively than on the web, which the test's pinned hash caught.
    - **The match's code makes its generator as each run starts** (`gen_system_body`): `tide_random_place(seed, tick, tide_this or no entity, site)`, a local, where `site` is a hash of the system's or handler's C name (`roll_site`). Nothing of the world is written, so the schedule has no rule for it and a system that rolls splits as ever (`compiler/tests/schedule/rolls`, and `Turn` in `platform/tests/jobs.tide`, on threads against one). A handler's also takes `tide_turn++`, a thread-local of the generated `.c` that `tide_world_tick_on` and the world's start set to 0 (only in a game where a match handler rolls: `handlers_roll`): which of the tick's runs of rolling handlers it is, as handlers run one at a time on the tick's thread.
    - **Local code's is `tide_l->tide_dice`**, a field of `tide_local` only in a game whose local code rolls (`program.rolls_local`), which `tide_local_frame_time` stirs each frame's length into: measured frames differ run to run, made-up ones (a run with no window) don't. No host seeds it, and a web reload starts it over.
    - **Functions and methods are handed both**: `decl.rolls` and `decl.reads_seed`, set where the code rolls or reads the seed (`check_random_use`) and passed up the calls (`mark_roll_callers`, once before systems are checked, so that what a system calls is known as its body is checked; and again in `check_roll_calls`, which reports the callers that can't and sets `program.rolls_match`, `rolls_local` and `uses_seed`). Their hidden parameters are `tide_random *tide_dice` and `const int32_t tide_match_seed`, after `tide_w` (`gen_routine_signature`, `gen_routine_call`, `match_seed`); a function that takes an Action is inlined, with `tide_match_seed` declared in its block (`gen_inline`).
    - **`Random.seed`** is an `E_MEMBER` whose `c_constant` is the sentinel `tide_match_seed`, which codegen writes as where the code has it (`match_seed` in `codegen.c`): `tide_w->Time.seed` in the match's code and its tasks, `tide_match_seed` in a function, and in local code (views, local handlers, local tasks, `Sample`) `tide_l->tide_match_seed`, a field of `tide_local` that `tide_frame` sets from the world it's given (0 with none), only in a game whose local code reads the seed (`program.seed_local`). The seed is still `Time`'s last field underneath (`program.seed`), which `time.seed` names as an error with the rename, and editors leave out of `Time`'s members.
    - **It rolls wherever a roll can mean something** (the owner, 2026-10-08, of a first version that refused these: "if it could we should do the extra work to get it usable there"). Codegen finds what rolls by walking the code (`stmt_rolls`, `expr_rolls`: a `CALL_ROLL` or a call of something with `rolls`), not by a mark of the checker's:
      - **A parallel loop's steps**, and a foreach over a grid whose steps run at once (`own_cell_only_expr` takes `CALL_ROLL` and functions that roll): where the loop is, `tide_par_dice = tide_random_fork(tide_dice)` (two rolls of the code's generator), captured as the loop's last capture (`par_captures`), and each step makes `tide_random_step(tide_par_dice, x, y, z)` of its place its own `tide_dice` (`gen_par_nest`). A list loop that rolls is never batched four at a time (`flat_list_expr` refuses the call). `Crackle` in `platform/tests/jobs.tide` runs one on threads against one thread.
      - **A sort's comparison** that rolls captures `tide_dice`, a pointer (`sort_captures`).
      - **A task** has `tide_dice` as a field of its frame when its function rolls (`add_task`), so it's the task's state, in its world's snapshots and hash, and part of its frame's fingerprint. `gen_task_start` and an await's child frame fork it from the generator of the code that starts it (which rolls too, by `mark_roll_callers`); a handler that's a task gets it in its dispatcher: `tide_random_place` with `tide_turn++` in the match, a fork of `tide_l->tide_dice` in the local world.
      - **`Sample`** (`gen_sample`): `tide_l->tide_dice`, through a cast, as the host's local state isn't const; a host that passes no local state gets a static of the function's. `Random.seed` there is `tide_l ? tide_l->tide_match_seed : 0`.
      - **An `audio` declaration** (`gen_effects`): its wrapper copies a `tide_random` out of the 8 bytes after its own state (`rolled_at`: the state's size, to the next 8), seeds it from `++tide_audio_rolled` (a static of the generated `.c`: one thread renders) where it's 0, hands it to the function and copies it back. Such an effect's `state_size` is both, as a host that calls it has to give all of it, and the two together are `TIDE_AUDIO_STATE_BYTES` at the most: an error of tidec's at the state parameter (`check_audio_sizes`: see Rendering and platform, Audio), with a `_Static_assert` behind it. It was the last 8 of the 4,096 bytes every voice had, until a state could be a megabyte.
      - **An operator** is handed both as a function is (`gen_operator_call`). One used where no code runs, a default's or a constant's, has no generator to be handed: the checker keeps those uses apart (`checker.bare`, from `note_operator_call`) and `check_roll_calls` refuses the ones whose operator turns out to roll.
    - **Refused for good** (`check_random_use`, and `check_roll_calls` for what reaches them through a function): `Sanitize` (call sites say `sanitizing`), `Interpolate`, and `Random.seed` in an `audio` declaration. Frags and verts roll (below). A constant's or a default's is "must be a constant".
    - A roll sets `Random`'s `named`, so the header includes `tide/random.h`. A game with no roll on the type and no `Random.seed` generates the C it did, byte for byte (old and new tidec over every game's source list, with `--layout` and without: 261 games the same; the capture test's game differs, whose view reads the seed from local state now, and the three whose tests use what's new only compile with the new one).
    - Tests: `compiler/tests/e2e/rolls` (the seed, entities, systems and ticks apart, a tick run again from a snapshot, a handler's two runs, steps of three kinds of loop and a foreach, a shuffle, an operator, tasks across their waits and from a snapshot taken while they wait, a handler that's a task, `Sample` with local state and with none, a pinned hash every platform shares, views, a local handler, a local task and a view with no match), `compiler/tests/e2e/effects` (noise: two voices, and a voice's next block), `compiler/tests/errors/roll_*.tide`, `random_member_unknown`, `random_seed_*` and `random_time_seed_renamed`, `compiler/tests/schedule/rolls`, `lsp_random`.
    - Not built: a host's seed for local code. An audio state struct over 4096 bytes was never refused by tidec, with or without rolls: the mixer's buffer is that big, and code that writes past it writes over the next voice.
  - **Frags and verts roll, and read `Random.seed`** (built 2026-10-08, by the owner's rule above, that it rolls wherever a roll can mean something; every choice is Claude's pick, Provisional in `docs/spec.md`, Random numbers). `docs/game/shaders.md` (Random numbers, with the live `grain` example) and `docs/language/math.md` (Rolls on the GPU) are the users' pages. What's built, and what code relies on:
    - **The checker lets them** (`check_random_use` in `compiler/src/check.c`: in a frag or a vert it only notes `decl.rolls` or `decl.reads_seed` on the `DECL_SHADER`, with `Random`'s `named` and the program's `uses_seed`), and `check_roll_calls` passes a call from one of a function that rolls or reads the seed. `mark_roll_callers` already carried both flags up from the functions a frag or vert calls, which is what the shader writer goes by. `check_roll_calls` then sets `program.rolls_local` for a frag or vert that rolls, so the local state has `tide_dice`, and `uses_seed` for one that reads the seed.
    - **The generator is a variable of the stage's own, `tide_dice`** (`uint tide_dice;` in GLSL, `var<private> tide_dice: u32;` in WGSL: `put_dice_variable` in `compiler/src/shader.c`), which `tide_roll()` steps: not a hidden parameter, so a function is the same text whichever stage reaches it, and nothing is passed. It's declared for a stage whose frag or vert rolls (`stage_rolls`), or whose text calls `tide_roll` at all.
    - **32 bits of state, as these GPUs have no 64-bit integers:** a linear congruential step (747796405, 2891336453) and PCG's RXS-M-XS output (`H_ROLL`). So not `tide/random.h`'s numbers. What's made of the 32 bits is that header's formulas, a helper each (`H_ROLL_INT` to `H_ROLL_QUATERNION_ROTATION`, written once in the GLSL both languages can say; `roll_calls` maps a call's `c_callee` to its helper): ints scaled down by the high half of a product, which `tide_mul_high` works out in halves; floats 24 bits over 2^24; a vector's components a statement each, x first. **A change to a formula in `tide/random.h` goes to its helper, and a roll `Random` gains gets a line in `roll_calls`, or its error there says it isn't on the GPU yet.**
    - **A stage makes its generator as its `main` starts** (`put_dice`): `Math.Hash` (the shader's `tide_hash4`, `tide_hash3`) of what tells one run from another. A frag: its pixel's place in the destination's own pixels from the top left (`gl_FragCoord` as `this.position` reads it, `tide_at.xy` in WGSL), and which instance of its draw the pixel is of, which the vertex stage passes on as a flat varying, `tide_nth` (one more of the 15 a draw's pixels read, counted in `plan`). A vert: `gl_VertexID` and `gl_InstanceID`, and in WGSL `@builtin(vertex_index)` and `@builtin(instance_index)`, which the vertex entry point takes when either stage rolls. No backend draws with a first instance or a base vertex (`gpu.h`'s `draw_indexed`), so those are the same numbers everywhere: a backend that starts to has to keep them so. Both also take the frame's number exclusive-or'd with which frag or vert it is (`roll_site`: FNV of its name in the shader, 31 bits, a literal in the text).
    - **The frame's number is a word of the draw's ints** (`shader.rolled_at`, laid out in `plan` after the lists' counts; `shader.seed_at` is the seed's, for a shader whose vert or frag reads `Random.seed`, which `ex_static` writes as that word). Generated `tide_frame` rolls it once as it starts, `tide_gpu_rolled = tide_random_next(&local->tide_dice)`, and sets `tide_gpu_seed` to the drawn world's seed (0 with none): thread-locals of the generated `.c`, as `tide_turn` is, which each `tide_shade_<n>` copies into its uniforms (`shaders_roll` in `compiler/src/codegen.c` says whether a game has either). **The same for every draw of a frame, on purpose:** the draw list joins draws whose uniforms are the same bytes, and a number a draw would have split every run. So GPU rolls follow the local generator: other numbers every frame, the same every run with no window, and a view's own rolls come after the frame's.
    - **Whole numbers, so the same on every backend:** `tide_platform_shaders` works each pixel's rolls out on the CPU and expects those bytes from OpenGL 3.3, WebGL 2 and WebGPU.
    - **Order within an expression isn't promised on OpenGL:** GLSL leaves which operand of an operator is worked out first to the compiler, where the CPU's code hoists what rolls into statements (see Evaluation order). The docs say to give each roll a statement where it matters; hoisting them in `shader.c` is what it would take. **A `?:` with a roll in it is a `tide_pick` in both languages** (`rolls_in` in `ex`'s `E_CONDITIONAL`): WGSL's `select` works both sides out and GLSL's `?:` one, each in an order of its own, where a function's arguments are worked out left to right in both, so both sides' rolls are made, the first side's first, on every backend.
    - **`liftable` says no to anything that rolls** (a call of a function with `decl.rolls`, an operator that does): what it allows is written twice in the shader, which would roll twice. So a Sample that's `Filter.Trilinear` at a place made of a roll is an error with words of its own (`has_roll`), and one that leaves its filter to its Texture reads the texture's own pixels there, with the warning there was.
    - **A `Random` value stays refused** (the type, its methods, `Random(seed)`: `check.c` and `type_fits` in `shader.c`), with errors that say to roll on the type: its state is 64 bits.
    - **Generated C and shader text are what they were for a game with no roll and no `Random.seed` in GPU code,** byte for byte: old and new tidec over every game's source list, with `--layout` and without, 265 games the same; the three that use it (the shaders test, the new e2e test and the docs' `grain` example) only compile with the new one. A shader that rolls has another `id`, as its text and its uniform count are other.
    - **Not built:** a set order for rolls in one expression on OpenGL; a number for each draw, so two draws that don't join roll apart where they overlap; a `Random` value on the GPU; holding a frag's rolls still across frames (that's `Math.Hash` of `this.position`).
    - **Tests:** `compiler/tests/shaders/rolls` pins the GLSL and WGSL (every roll in a frag, a vert, a function both reach, the seed alone, a vert with no frag); `compiler/tests/e2e/gpu_rolls` (no GPU, natively and under Node: three draws through a frag that rolls are one run, the word they send is the frame's roll and another the next frame, the seed's word with a match and with none, which stages have the generator, and the view's own rolls going on after the frame's); pass 19 of `platform/tests/shaders.tide` with `run_roll_checks` in `shaders.c` (a pixel's three rolls byte for byte, the pixels beside it, two instances of one draw, a vert's rolls blended between corners, a frag behind a vert that both roll through one function, a blit's frag over a whole destination, every roll within its range 24 times over at each pixel, the seed, and each of them another color a frame later), the same on OpenGL 3.3, WebGL 2 and WebGPU, where the device is then lost and found; `compiler/tests/errors/roll_in_frag` (Trilinear at a rolled place), `random_in_frag` and `random_in_gpu_function` (the value); `lsp_random` (completion, hover and signature help in a frag and a vert). Not run: Android, and OpenGL on a Mac.
  - `Random` is a built-in struct with one field, `long state` (`program.random`), whose C type is `tide/random.h`'s `tide_random`: generated C never declares it, and only includes that header in a game that names `Random` (`decl.named`). Its methods are built-in signatures with the owner `Random` (`compiler/src/builtins.c`), checked as a struct's `mut` methods are (`CALL_RANDOM`), so a system that rolls says `mut` for what the generator is in, and the schedule needs no rule of its own. The GPU has none of the value: `shader.c` refuses the type, its methods and `Random(seed)`, saying to roll on the type, which frags and verts do (above).
  - The generator is PCG32 with a 64-bit state. Any state works; 0 is one nothing seeded, which the engine seeds (`gen_seeding` in `compiler/src/codegen.c`, `tide_random_seed_place`): a component's fields as a spawn or an Add applies, when the entity's handle is final (a split system's is temporary until it settles), from the match's seed, the tick, the handle and which field it is; a match singleton's as the match starts; in the local world, from the handle or the field alone. Only fields, and structs in fields: not lists, maps or grids.
  - The match's seed (`Random.seed`, `w->Time.seed` in C) is an int from 0 to 2147483647. It's `Time`'s last field while code is checked, and dropped again unless the game reads it, rolls on the type in the match's code, or has a `Random` in the match's components or singletons (`drop_unused_seed` in `compiler/src/check.c`, `program.uses_seed`): a game that uses none of this has the world, the header and the hash it had, which the pinned numbers show. A server picks the seed as it starts a match, from `tide_server_desc.entropy` (a session's `tide_session_desc.entropy`; `tide/host.h` gives `tide_platform_entropy`, `platform/src/entropy.c`, but to a run with no window or with `--seed`, which gets none), and without one the desc's `seed`, which is 0 unless the host picked one (`--seed <n>`), so tests, benchmarks and runs with no window repeat. Clients never send it: it comes with the world, and a player who starts the match itself (`pure_start`) is told it with how the match started (the hashes' message in `engine/src/session.c`).
  - A `Random`'s methods are calls that write (`writes` in `compiler/src/codegen.c`), so rolls keep their turn like any other: in `float2(random.NextFloat(), random.NextFloat())`, x is rolled first on every platform. `compiler/tests/e2e/evaluation_order` checks it.
