## Packaging and releases

### Rooms

The menu that comes with tide (the owner asked for it 2026-10-07: "a starting menu for games to quickly get up and running", so a game has host and join "but just focus on the game until I need to re-design that part"; that it's a package a game lists, and that Towers, Sumo and the samples use it so an issue is fixed everywhere, are the owner's; the rest is Claude's picks, in the package's `README.md`): `packages/rooms/`, namespace `Rooms`, a page of Tide and no C. A game lists `rooms` in its `tide.packages` and opens on a title page (its name, Play, Host a room, Join a room), has a page to type a room's code into (Enter joins), the room's page (the code and Copy, or Invite friends for a match that's closed; who has each seat, when the game says; Resume, New game and Bots on/off when it says; Leave the room), and a Menu button in the match, which Escape opens too. Its design is the one Towers' and Sumo's lobbies had (see The physics games), and `rooms.tide` says what a game reads of it. What code relies on:

- **It's drawn over a live match:** `Main` stays the match's, and the match runs behind the title. A machine told which match to be in (`--host`, `--join`, `?host`, `?join=`) has no page in its way (`Begin` decides once, `lobby.started`); `Disconnected` puts a machine back on the title, in a match of its own, with a line that says why; `Connected` closes a page for a machine that was joining.
- **The pages are modals of the GUI's own widgets** (`GUILayout.Modal`), in whatever theme the game sets, with no drawing of the package's: so they're over everything the game draws whatever its layers (a package's view can't name the game's `Layers`, and its views run first, as a package's files compile first), and the devices are the GUI's while a page is up, which hides them from the input's `Sample` and the game's views with no claim. Back (Escape, a gamepad's east button) closes the modal on top, which the view reads as its page's own way out (`open`, a local set true each frame: Join goes to the title, and the title and the room into the match); a page that follows another in the same frame is drawn then, so nothing flickers. `Lobby.playing` says the player's hands are on the game: no page is up, the match is here, and the pointer that pressed the last page's button is let go (a key that clicked it is the GUI's until it's let go, by the GUI's own rule).
- **What a game says and hears is fields of `Lobby`:** `seats`, `manned`, `mine`, `bots`, `offersNewGame` and `offersBots`, which a view of the game's writes each frame (the game's views run after the package's), and `newGame` and `toggleBots`, true for the frame a button was pressed in, which `Begin` clears the frame after: a game sends its own commands from them, as a package's function can't `Send`. Nothing of a game's match is in the package.
- **Three functions are `virtual`,** for the game to `override`: `Rooms.Title()` (`Application.title`), `Rooms.Tagline()` and `Rooms.MenuButton(screen)` (the bottom left corner: the stats' is the bottom right).
- **Two things the engine gained for it** (2026-10-07), as a package can name nothing of the game's: `Session.Start()` with no scene starts a match in `Main` with its defaults (`check_session_call`, an error where `Main` is local), and `Application.title` is the game's `title` setting, or the program's name (`tide_game_title` in the generated `.c`, only in a game that reads it: `program.uses_title`). Both are documented (`docs/multiplayer/matches.md`, `docs/spec.md`) and tested (`tidec_e2e_session_main`, `compiler/tests/errors/session_start_local_main.tide`).
- **Outgrowing it is copying `rooms.tide` into the game and dropping the line:** it's written with nothing a game can't use.
- Tests: `tide_rooms_lobby` (`packages/rooms/test/`: where the pages leave a machine by how it started, what each button asks of the session, driven by the keyboard as a player would, and what the game reads); Towers' and Sumo's tests of their lobbies, which read `local.Rooms_Lobby`; the docs' page under Matches (A menu that comes with tide).
