## Packaging and releases

### Rooms

The menu that comes with tide (the owner asked for it 2026-10-07: "a starting menu for games to quickly get up and running", so a game has host and join "but just focus on the game until I need to re-design that part"; that it's a package a game lists, and that Towers, Sumo and the samples use it so an issue is fixed everywhere, are the owner's; the rest is Claude's picks, in the package's `README.md`): `packages/rooms/`, namespace `Rooms`, a page of Tide and no C. A game lists `rooms` in its `tide.packages` and opens on a title page (its name, Play, Host a room, Join a room), has a page to type a room's code into (Enter joins), the room's page (the code and Copy, or Invite friends for a match that's closed; who has each seat, when the game says; Resume, New game and Bots on/off when it says; Leave the room), and a Menu button in the match, which Escape opens too. Its design is the one Towers' and Sumo's lobbies had (see The physics games), and `rooms.tide` says what a game reads of it. What code relies on:

- **It's drawn over a live match:** `Main` stays the match's, and the match runs behind the title. A machine told which match to be in (`--host`, `--join`, `?host`, `?join=`) has no page in its way (`Begin` decides once, `lobby.started`); `Disconnected` puts a machine back on the title, in a match of its own, with a line that says why; `Connected` closes a page for a machine that was joining.
- **The pages are modals of the GUI's own widgets** (`GUILayout.Modal`), in whatever theme the game sets, with no drawing of the package's: so they're over everything the game draws whatever its layers (a package's view can't name the game's `Layers`, and its views run first, as a package's files compile first), and the devices are the GUI's while a page is up, which hides them from the input's `Sample` and the game's views with no claim. Back (Escape, a gamepad's east button) closes the modal on top, which the view reads as its page's own way out (`open`, a local set true each frame: Join goes to the title, and the title and the room into the match); a page that follows another in the same frame is drawn then, so nothing flickers. `Lobby.playing` says the player's hands are on the game: no page is up, the match is here, and the pointer that pressed the last page's button is let go (a key that clicked it is the GUI's until it's let go, by the GUI's own rule).
- **What a game says and hears is fields of `Lobby`:** `seats`, `manned`, `mine`, `bots`, `offersNewGame` and `offersBots`, which a view of the game's writes each frame (the game's views run after the package's), and `newGame` and `toggleBots`, true for the frame a button was pressed in, which `Begin` clears the frame after: a game sends its own commands from them, as the package knows none of a game's commands. Nothing of a game's match is in the package.
- **Three functions are `virtual`,** for the game to `override`: `Rooms.Title()` (`Application.title`), `Rooms.Tagline()` and `Rooms.MenuButton(screen)` (the bottom left corner: the stats' is the bottom right).
- **Two things the engine gained for it** (2026-10-07), as a package can name nothing of the game's: `Session.Start()` with no scene starts a match in `Main` with its defaults (`check_session_call`, an error where `Main` is local), and `Application.title` is the game's `title` setting, or the program's name (`tide_game_title` in the generated `.c`, only in a game that reads it: `program.uses_title`). Both are documented (`docs/multiplayer/matches.md`, `docs/spec.md`) and tested (`tidec_e2e_session_main`, `compiler/tests/errors/session_start_local_main.tide`).
- **Each page is a `virtual` function** (the owner, 2026-10-11, of customizing a package's UI: "i think the `override on page` idea is good and I like it"; the names and shapes are Claude's picks): `TitlePage(session, lobby)`, `JoinPage(session, lobby)`, `RoomPage(session, room, lobby)` and `SettingsPage(lobby)`, which the `Pages` view calls for the page that's up, in the order the pages' blocks had (Settings, Join, Title, Room: a page that follows another in a frame is drawn then). `Pages` keeps its name, as games order their views by it (`[Before(Rooms.Pages)]`). What code relies on:
  - **What a button does is a function each** (`Play`, `Resume`, `Host`, `Invite`, `ShowJoin`, `Join`, `LeaveJoin`, `ShowSettings`, `LeaveSettings`, `CopyInvite`, `CopyCode`, `Leave`), which the package's own pages call, so a game's page keeps the flow without knowing `Lobby`'s fields.
  - **The calls ask the session themselves** (`Session.Open`, `Join` and `Start`, `Clipboard.Copy`), as functions can since 2026-10-11 (`notes/language.md`). The first version, the same day, had them set a `Lobby.ask` that `Pages` did, as functions couldn't yet: that's gone. `RoomPage`, `CopyInvite` and `CopyCode` are still handed the room's code and invite, as a function can't read `session.room` or `session.invite`.
  - **An override has the parameters of what it replaces,** so a page of the game's gets `Session` and `Lobby` and nothing else. One that needs the game's own state or `Devices` is a view of the game's that draws when `lobby.page` is that page, with the package's page overridden by an empty body. Documented so.
  - The pages' behavior is what it was: `tide_rooms_lobby` passed unchanged, and every game that lists `rooms` built with no change (none of the new names clashed under `using Rooms;`).
  - Validation on Windows, with `tide eject`: 2,082/2,082 native and 2,054/2,054 web debug tests, and the docs production build.
  - `tide_rooms_pages` (`test/pages.tide`, `pages_test.c`): a game whose title is an override with buttons of its own, and whose settings are its own view; the override is what's drawn (no modal), its buttons take the menu where the package's would and ask the session what they would, its own view's button asks the same way, and the room's page is the package's still.
- **Outgrowing it is `tide eject rooms`** (see `notes/cli-and-packages.md`), which was copying `rooms.tide` out of the installation by hand: it's written with nothing a game can't use.
- Tests: `tide_rooms_lobby` (`packages/rooms/test/`: where the pages leave a machine by how it started, what each button asks of the session, driven by the keyboard as a player would, what the game reads, and a finger's tap on Play with the mouse resting on the title, which was lost: see `notes/gui.md`); Towers' and Sumo's tests of their lobbies, which read `local.Rooms_Lobby`; the docs' page under Matches (A menu that comes with tide).

- **Volume settings (2026-10-09):** Settings on the title and room opens `Page.Settings`, a modal with a Volume slider from 0 (mute) to 1 (full volume). Back or Escape returns to `Lobby.settingsFrom`, the menu that opened it. `Lobby.volume` starts at 1 and belongs to local state, so it survives starting, joining and leaving matches while the game is open; it is not saved between program runs. `Volume` applies it every frame, including play and joining, because audio bus gains reset each frame. `Audio.SetVolume(Sound { }.bus, lobby.volume)` selects the default sound's master bus, with the game's own `[Bus]` enum type when present, so the package declares no buses and needs no runtime API of its own. Games' later views can still set bus gains themselves. The settings page uses the same modal/input rules as the other menus; no match commands are sent by its controls. Integration tests cover keyboard navigation and actual frame gains with a namespaced game bus enum; compiler audio fixtures cover default sounds with and without a bus enum. Full native and web builds passed, with 2,009/2,009 native tests and 1,981/1,981 web tests; the docs production build passed. Scripted Towers captures were inspected at 1280 by 720 and 390 by 780, with the settings modal fitting both sizes.

- **The invite (2026-10-21):** the room's page copies `session.invite` (`CopyInvite(lobby, invite)`, new), so on the web a player hosts, copies a link and sends it, and opening it joins the room (`?join=`, which the package already obeyed: `Begin` leaves a joining machine on the Join page's wait). The button says **Copy the invite link** where the invite is a link (`invite != room`) and **Copy the code** where it's the code (desktop, Android); the label above it still shows `Code K7QF2M`. `RoomPage` is `RoomPage(session, room, invite, lobby)` now, as a function can't read `session.invite` either: a game's override takes the new parameter (Inside Out's empty one in tide-prototypes changed with it). `CopyCode(lobby, room)` stays, for a page that offers both. The local behind "Invite friends" was renamed `asked`, as `invite` is the parameter. Test: `rooms_copies_the_invite` (the code with no link, a host's link, nothing while the room has no code). Engine side: `notes/webrtc-and-rooms.md`, Session.invite.

Confirmed-presentation ABI integration (2026-10-11): the page override fixture supplies NULL/1 for confirmed previous/fraction, preserving its single-world GUI behavior. It is covered by the merged full native/web suites recorded in notes/testing.md.
