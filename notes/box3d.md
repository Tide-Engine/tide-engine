# The Box3D package

## All-hit queries and live ignore-body parity (2026-10-18)

The owner approved `RaycastAll`/`CastAll` and ignore-body overloads after the
prototype gap review. Live `Physics` and detached rewound `Query` now have
`RaycastAll(from, to, out List<RayHit> hits, bool includeSensors = false)`
and an overload with `Body ignore` before the optional sensor flag.
`CastAll` has the same forms for `Box`, `Sphere` and `Capsule`, retaining
`shape, from, rotation, to` order. Named arguments are `ignore: body` and
`includeSensors: true`; sensors are excluded by default. Live closest-hit
`Raycast` and `Cast` now also support `ignore: body`, matching Box2D and the
existing rewound overloads. Ignoring uses the whole native handle including
generation, and excludes all the body's shapes, including parts.

Each collider contributes its first hit. Results sort by increasing fraction,
then the complete shape-handle tie order used by the closest-hit method.
Separate colliders on a body remain separate even if their `entity` and `part`
match. A mesh contributes one hit for the whole collider, not every triangle,
entry or exit. The methods replace the destination list, return whether it has
any hits, and give an empty list for an unstepped world, invalid cast inputs
or an invalid/empty rewind context. Results are ordinary `RayHit` values for
game filtering and match/local retention, snapshots and packing. Existing
live deletion exclusions and captured-context retention remain in effect.

The native callback collects actual hits in 32 stack slots and grows only as
needed, retaining the full sweep by returning 1. Box3D's native mesh query
already returns the first intersection of each shape. Results are sorted once
and written through a checked `out List<Found>`; all native record bytes are
cleared before assignment, including padding. Growth arithmetic is bounded
by the runtime's 1 GiB output-list byte limit and uses its existing fatal
allocation failure path, without a smaller hit cap or silent truncation.
Tide maps records through `Met`. No global query storage, public result field,
body/physics ABI or resident-world representation changed. The native filter
gained ignore-body and sensor flags; closest-hit queries retain early pruning.

The detached path reuses the existing BVH candidates and `SceneRay`/`SceneCast`
narrow phase. Candidates are in collider-array order, with each mesh's
triangles contiguous. `AddSceneHit` therefore merges those adjacent triangle
answers in linear time, retaining the nearest one (first triangle on a tie),
before sorting collider hits by the same fraction/shape keys. A starting cast
overlap retains fraction 0 and zero normal; no unique surface point is
specified there. Rays still skip shapes they start inside, with either sensor
option, as before.

`test/query_all.tide` and `packages/test/query_all_test.h` cover rays and all
three cast shapes, closest/all-first agreement, equal-fraction order,
compounds/parts, sensors, old versus reused body handles, gameplay filtering,
empty/nonfinite/overflow queries, first-step availability, initial overlaps,
70-hit growth, fractional rewind, deletion and retained contexts, local/match
result retention, snapshot/pack/restore, and serial/job-pool equivalence. A
two-plane mesh verifies exactly one hit per collider in both live and detached
paths. The public-hit digest `f8d8985883f8ec9f` matches native/WASI debug and
release. Full debug suites passed (native 2374, web 2284); both query fixtures
passed in native and web release, and the docs build passed. Existing physics
and resident pins remain unchanged. User references are `README.md` and
`docs/packages/box3d.md`.

Scene visibility unification (2026-10-15): removal of generated scene audience
fields changes complete-world/world-sequence pins in stack, course, sleep and
mesh (mesh sequence now afa0b803e82fedb1). Native and WASI agree. Body, resident
digest and query-answer pins remain unchanged; no bridge or vendored physics
implementation changes. Validation is in notes/language.md.

## Static mesh colliders (2026-10-15)

The owner requested mesh collider support. `MeshCollider` now accepts
`List<float3> vertices`, zero-based triangle `List<int> indices`, `scale`
(default 1), `offset`, `friction` (0.6) and `bounce` (0). It attaches to a
static `Body` or its `Part`, preserving concavity. Geometry and material
are read once, as for other shapes. An unsupported body or invalid mesh
makes no shape; an unsuccessful mesh part is destroyed. An attachment is
attempted once. Bodies with attached meshes remain static when another
type is requested; position/rotation writes still work. Naming, limits and
these detailed failure policies are implementation picks, provisional with
the rest of the package API. No language or engine runtime API changed.

Native attachment systems read the actual list handles through rows,
derive counts and flatten checked source lists internally. There is no
callable Tide extern taking a caller-supplied buffer length. `MeshMade`
is a dense one-bool marker because extern systems cannot filter sparse
components. `PrepareMeshParts` temporarily places the native body handle in
`Part.mesh`; attachment replaces it with the shape handle and registration
records its entity. Removal follows the existing part/body lifecycle.
The step remains one named phase; meshes attach after existing primitives
and before Simulate. `Part` grows from 32 to 40 bytes.

The cooker validates 3–65,536 vertices, 1–65,536 triangles, complete index
triples and every index, finite nonzero scale, finite offset and coordinates
after baking within ±1,000,000 per axis, finite nonnegative friction and
finite bounce in [0, 1]. These bounds also keep native intermediate area,
BVH cost and byte/count arithmetic in range on wasm32. Degenerate triangles
are discarded by Box3D; an entirely degenerate mesh is rejected. Mirroring
flips input winding when cooking, retaining outward/front orientation.
There is no sensor/density field, per-triangle material API, mesh query
probe or automatic rendering-mesh conversion.

`b3World_InternMesh`, a Tide-marked addition to the vendored library, copies
and deduplicates cooked bytes through the world's existing canonical
geometry store and hash buckets. It never caches the temporary cooker's
address, which can be freed and reused. Temporary cooked data is freed;
retained data belongs to the resident arena and the canonical snapshot.
Interning/creating meshes conservatively marks all resident pages. Unique
geometry remains until world destruction, like existing box hulls.

Current queries include meshes through Box3D. Detached query/history scenes
store one value-only Collider per triangle (`count == 3`), preserving the
existing 176-byte ABI and BVH. Ray and shape casts use Box3D's mesh narrow
phase over a stack-owned one-leaf triangle, including front-face rejection;
overlaps use the existing distance path. No native geometry pointer escapes
into a scene. Preparation/history memory scales with triangle count;
disabled history captures none. Expanded counts and output capacity are
checked before allocation/copy. Existing scene limitations at extreme
allocation exhaustion remain; the package arena is still 64 MiB.

`tide_box3d_mesh` covers collision versus a gap, all current/rewound primitive
queries, front/back rays, initial overlap, mirrored/rotated parts and current
non-opted geometry, historical pose interpolation, retained contexts, source
edits, type changes, destruction, snapshots, canonical restore, replay,
chunked vertex/index lists, invalid indices/degenerates and nonfinite data.
Its simulation sequence is `870764faa96485c3` on Windows and WASI.
`tide_box3d_mesh_join` reuses the fresh-process full-state/delta host with
this scene. Network deltas transfer between native and WASI in both
directions, with initial and ten-ticks-later hashes equal. Full world packs
remain the existing platform-local raw-header format; the network delta
format is used for cross-platform transfer.

The course fixture's parts/asking world pins change for the larger Part;
body, resident-digest and answer pins are unchanged. Sumo's two network pins
also change: adding the components shifts the compiler's existing automatic
Brain.dice spawn salt from 3072 to 3584. Generated old/new C confirms that
cause; native/WASI agree at ticks 640 and 880. Physics rules and RNG algorithms
are unchanged.

Validation: Windows clang 23.1.2, local Node 24.16.0. The complete debug
suites ran 2,339 native and 2,252 web tests; their only failures were the two
explained Sumo hash pins. After updating those pins, all eleven Box3D/Sumo
targets pass on both platforms, including full-arena checks, original

The final four mesh cases additionally pass on both platforms after adding

Merged origin/dev's unrelated frustum-culling work cleanly. Rebuilt both

## Packaging and releases

### Box3D

The Box2D package again, for Erin Catto's Box3D: `packages/box3d/`, namespace `Box3D`, its C functions `b3t_`, the same experiment on the same terms. The public rules are shared: every change made by the package's systems from components, a world at rest not stepped, the step on the tick's threads through jobs, its systems as one stage with `[Before(PhysicsStages.Step)]` the way in ahead of it (its shapes' systems at offsets 3 to 5, its parts' at 6 to 8, `Simulate` at 9, `Leave` and `Report` at 10), a new body's impulses given by the step, a body that code moves waking with what it touched, gravity that changes waking the world, sensors, `[Position]` and `[Rotation]` on a `Body`'s `position` and `rotation`, and `tide_box3d_order` and `tide_box3d_course`. How the match holds Box3D's memory differs since 2026-10-07: resident pages, below, where Box2D still writes an image into a list. Its page for users is `docs/physics/box3d.md`.

- **The bridge mirrors the generated `Physics` ABI.** With maps carrying insertion-order cursors, each map is 24 bytes aligned to 8 and `Physics` is 176 bytes; `owners`, `parts` and `sensors` start at 96, 128 and 152. Four explicit padding bytes follow `goneShapes` at 120, matching tidec's padding before `parts`. The bridge asserts every Physics field's offset as well as its total size against this layout. This changes the match representation and therefore its world hash pins, including the stack, course, sleep and Sumo matches; body, resident-digest and query-answer pins remain checks of their existing behavior. There is no physics rule change.
- **Resident state (2026-10-07)** is for libraries that come with Tide, as the owner asked ("for ours only i think is fine to start with"); its interface and other picks remain Provisional in `docs/spec.md`, C functions. `Physics.state` is a `Resident`, in place of `Physics.image`, `Physics.geometry` and `Physics.size`. The stamp still hashes the previous stamp and everything done to the world since. What code relies on now:
  - **The persistent memory is the world's.** `tide/resident.h` keeps one 64 MiB arena for Box3D at a fixed address for the process. `b3Alloc` uses `tide_arena_alloc`, including geometry and the allocator's own state. After a step `b3World_TouchChanged` and the bridge say what may have been written, then `tide_arena_commit` copies every touched 16 KiB page into the resident. Untouched pages stay shared with older worlds. The marks are conservative: touched pages are copied without comparing them first; a call whose writes aren't followed, or a world with most bodies awake, can mark all of them. A world at rest has neither a step nor a commit.
  - **A rollback copies pages back, without making Box3D again.** `restore_state` checks page identity, even when the stamp matches, and `tide_arena_restore` copies the pages that differ or have uncommitted writes. Two runs of the same simulation can have different local allocations. A world at another tick in the same process uses the same arena, as does a query of another state; that query restores its world's pages, and the next tick restores its own. Box3D's global world struct is saved in the arena and loaded with it; system scratch, callbacks and this build's constants are relinked, not restored as old pointers.
  - **The hash and the network use canonical state.** The world's hash reads the resident's stamp and digest, never its arena bytes or pointers. `b3World_Digest` covers counts, awake body simulations and their contacts' impulses; it isn't a hash of every arena byte. The library's packer writes the stamp, a canonical Box3D snapshot with its sections consecutive, and the geometry it names, only where a world is packed: joins, resyncs, host migration and reloads. Unpacking makes the receiver's arena and commits it. A delta currently carries those canonical bytes whole when the resident differs from its base. Ordinary ticks and local rollback serialize none of it.
  - **Released storage must be marked before it goes.** The release-only crash in `sumo_costs` was a stale contact array restored after its old allocation had been written, then reallocated or destroyed: the end-of-step touch pass saw only the replacement. `b3UnlinkContact` reached a null island contact array with index -1 during a rerun. The bridge's allocator release now marks the old allocation before `tide_arena_free`, and `b3FreeElement` marks its manifold free-list link. A full-arena byte check and a debugger watchpoint found the missing mark; the full optimized Sumo run with `B3T_CHECK_RESIDENT=1` then ended with exit 0. Separate safety fixes bound marked IDs by each array's count and mark destroyed shape/contact records without following the stale material/manifold pointers they hold.
  - **The full-arena check includes bytes the canonical image omits.** `b3t_check` compares every committed page with the live arena and reports its first unmarked write. Changed and released allocations, stale array tails after elements are removed, event arrays and task buffers all have to be preserved. These resident buffers are marked even where the next step clears them before reading them. The stack, workers' arenas and OS objects use `b3AllocScratch` outside the arena, and are relinked instead.
  - **Tree rebuilds mark what they wrote where they wrote it** (`dynamic_tree.c`). The old node array is marked before it becomes the spare, as it may already have been changed this tick. Leaf indices, leaf nodes and the selected heuristic's scratch are marked through the gathered leaf count, not their capacity. The new current nodes are marked by the end-of-step pass. A rebuild that returns without doing work marks neither its spare nor its scratch; the hooks also work on the solver's workers. The image-list section-placement costs below don't apply to these page commits.
  - **A fresh join knows the reader before its first tick.** `register_state`, a constructor in the bridge, registers the resident kind and its pack, unpack and relink functions as the game's library loads. Registering only when `OpenWorld` first runs would leave a joining process unable to unpack its first world. `tide_box3d_join` writes a full world and a delta, then reads each in a fresh process that hasn't ticked Box3D.
  - **Reload and lifetime.** A native reload with the same layout keeps the arena and adopts its registry from the host's local state; the new build relinks its callbacks and scratch. A changed layout or a web reload carries the resident through canonical bytes. The engine keeps a durable registry copy and releases an adopted local registry before the local world is cleared or freed, so those operations don't leave it pointing into old storage. Canonical size/write caching retains the page table it sized and checks its digest too.
  - **Pins and tests.** World hash pins changed intentionally with `Resident` replacing the image lists; `OWN_HASH` now pins the per-step resident digests through `b3t_image_hash`. The bodies' and query answers' pins are unchanged. The engine's `test_resident.c` and `tidec_e2e_resident` exercise allocation, page sharing and restore, world lifetime, canonical pack/unpack, deltas and cache lifetime. The package's stack, course, parts and sleep tests exercise the resident path, with full-arena checks; standalone Box3D image-in-parts tests still exercise the canonical writer and its marks. Timings for this representation are recorded separately from the historical image-list measurements below.

The remaining image-list notes in this section record the implementation before resident state on 2026-10-07. The public body, shape, event and query rules still apply, and the canonical writer still uses these serialization fixes. References below to per-tick images, `Physics.image` or `Physics.geometry`, image-list hashes and rebuilding a world for local rollback are historical; the resident rules above replace them.

- **What those call, and what an image in parts made of each before resident state** (2026-10-06; see An image is written as what changed, below):
  - A new body's impulses, at the step: `b3Body_ApplyLinearImpulseToCenter` and `b3Body_ApplyAngularImpulse`, which are followed, as when `Enter` makes them.
  - Waking a body that code moved: `b3Body_SetAwake`, which is followed since a body's `asleep` was built (below). `wake` only makes the call for a body that's asleep and not static, so a position written every tick costs nothing of it. Box3D has no `b3Body_WakeTouching`: `wake_moved` asks what touches the body (`b3Body_GetContactData`) and wakes each.
  - Gravity that changed: `b3World_EnableSleeping` off and on, not followed either, and everything is awake after it, so the next image is whole anyway. (`b3World_SetGravity` is a setting every image writes.)
  - Sensors: no call that changes the world. Every shape is made with `enableSensorEvents`, a bit of its `flags` in the image, and a sensor's is a made shape like any other (`b3CreateShapeInternal`). What a step does for a sensor it writes into the sensor's own arrays, which are a section an image in parts writes whole every time, and into no body, shape or contact. The step's sensor events are asked (`b3World_GetSensorEvents`), as its contact events are. Box3D's writer zeroed a visitor's two spare bytes already.
  - `tide_box3d_course` has every image in parts compared with the image written whole (`b3t_check`) through all of it: 181 of the match of sensors' 330 images are in parts.
- **A body's `asleep`** is as the Box2D section says of its own, rule for rule (the same picks, awaiting the owner; `docs/physics/box3d.md`, Bodies at rest), with `tide_box3d_sleep` for `tide_box2d_sleep`. What differs:
  - The two bytes are the two a `Body` had to spare after `stepBullet` (`FLAGS`: `bullet`, `stepBullet`, `asleep`, `stepAsleep`), so it's 176 bytes as it was. `flags_apart` says both pairs at once, for `written`.
  - **A body can be put to sleep where `Physics.sleeping` is off**, and stays so until something wakes it: Box3D's switch only says what the step does. `sync_body` asks Box3D what type the body is, so one that was made static in the same tick is neither asleep nor awake, and a sleeping one that's made static reads awake after the step (`Leave` asks).
  - **`b3Body_SetAwake` is followed by an image in parts, both ways** (`b3SnapNoteOp`, `box3d/TIDE.md`): `b3WakeSolverSet` and `b3TrySleepIsland` already said what they write, for the step, and the island that's split before it's put to sleep is of awake bodies, which are written anyway. So code that moves a sleeping body, changes how it is, wakes it or puts it to sleep no longer costs that tick's image whole by itself. It still does where a section of the image has to move, as when the step wakes a stack or lets one fall asleep: in a world that's all asleep, the first body to wake has no room where the awake ones go (`box3d_costs`: a crate put to sleep and woken in turn, in a world otherwise asleep, has all 60 of its images whole, 0.26 ms a tick). `tide_box3d_parts` has the cases: `yard.tide` wakes a stack from its bottom crate and puts it to sleep from its top one, another in ticks that follow each other, the ball in a tick that also pushes it, and a crate that's spawned asleep; Box3D by itself wakes a body and puts one to sleep at steps whose images have to be in parts (`where_one_line_says_so`: a body that never falls asleep by itself among them), and at random, right after a restore too.
  - **`Leave` reads no more of a body the step says nothing of than which it is**, as before, but in a tick whose step put bodies to sleep for code (`slept`): then, of each such body, the four bytes of its flags and what Box3D has its type as. A body the step says something of and didn't leave awake is asked whether it's asleep (`b3Body_IsAwake`), as it's asked where it is: one that fell asleep is, and one that code wrote to and the step left alone, a static body that was moved, isn't.
  - The same change to Box3D's sources as to Box2D's (`b3TrySleepIsland`), which `box3d/TIDE.md` had as a thing not fixed and `tide_box3d_parts` kept away from.
  - **Bodies spawned asleep are each a sleeping set and an island of their own**, which are sections an image writes whole whenever one changes: with thousands of them, the ticks in which many wake cost more than where they sleep a stack to a set. Sumo measured it (The physics games), and the docs say what to do instead.
  - **Pins.** The bodies' pin, Box3D's own images' (`OWN_HASH`) and what was answered (`ANSWERS_HASH`) didn't move: every image is the bytes it was. The worlds' did, each for the two bytes of the bodies that sleep in it and for what its stamps note of them.
  - What it costs: nothing that shows (six runs of each, old and new in turn): 1.86 ms a tick with everything moving where it took 1.97, 0.10 with one crate pushed where it took 0.12, 0.010 at rest where it took 0.011.
  - The pins moved with sensor events on every shape as Box2D's did: 24 bytes of the last image's 40,812, each a shape's `flags`, 66 to 67, with the bodies' pin as it was.

- **Five things the owner asked for of both packages (2026-10-06) are built here**: shapes on entities of their own, a body's type that changes, questions asked of the world, what's in a sensor and what meets hard, and tuning as fields of `Physics`. That the five are wanted, that shapes go on entities of their own (and not several of a component on one entity), and that tuning is fields of the singleton are the owner's. The names and the details are Claude's picks, listed under Provisional in the package's `README.md`, made from the same proposals the Box2D package's are to be made from: when that lands, the two are reconciled, name for name. Sumo uses none of them yet (see The physics games). What's built, and what code relies on:
  - **`Part { Entity of; }`** puts an entity's `Box`, `Sphere` and `Capsule` on `of`'s body. The systems that make a body's own shapes say `without Part`, and three more make a part's (`AttachBoxParts` and the like, after the bodies' own, so a game with no part has its shapes made in the order it did): each reads the body through its `World` (`world.TryGet<Body>(part.of, ...)`), keeps the shape's handle in the `Part` (`box`, `sphere`, `capsule`) and whose it is in `Physics.parts` (a map from a part's shape to its entity, with nothing in it for a body's own shapes), and destroys a part that has no body to be on.
    - **A part that goes takes its shapes** (`RemovePart`, a `Destroyed` handler: `Physics.goneShapes`, which `Begin` gives C before the bodies that went: `b3t_gone_shapes`, `b3DestroyShape`, noted `'h'`). **A body that goes takes its parts**: before C removes it, `Begin` asks C for its shapes (`b3t_body_shapes`, `b3t_body_shape`) and destroys the entity of each that's a part's. The part's own handler then finds its shape out of the map already, and lists nothing.
    - **`Touched` and `Parted` say which shapes**: `part` and `otherPart`, each the entity itself for a shape of its own (`PartOf`). They still go to the bodies' entities. C gives each event's two shapes with its two bodies (`touch`, `b3t_touch`). A shape that went by itself this tick is still named by the step's events, and Box3D no longer knows whose it was: `b3t_gone_shapes` keeps that for the tick (`parteds`), so such a parting says the body, which is still there, and no part.
  - **A body's `type`, `gravityScale`, `linearDamping`, `angularDamping` and `bullet` follow what code writes**, where they were read when the body was made. What Box3D has of each is in the component (`stepType` and the like, the package's own, after `bullet`), which is how `Enter` tells: nine more lanes looked at for every body every tick (`written`: the type against what Box3D has, three floats against three, and `bullet` against the byte beside it, which are one lane). `sync_body` sets the type first, so that a speed written with it is the new type's to have, and wakes a sleeping body whose other settings changed.
    - **`b3Body_SetType` isn't followed by an image in parts, on purpose** (measured: a tick that changes one costs 0.25 ms with 2,400 bodies asleep, against 0.010 at rest and 0.09 with one crate pushed): it goes through `b3TransferBody`, which nothing follows, lets go of every contact, and makes each shape's proxy again in another tree.
    - **It sends nothing for what still touches.** Box3D ends every contact of a body whose type changes and begins the ones that still touch in the step, so in a tick that changed a type (`retyped`), `b3t_touches` leaves out a pair of shapes that has both an end and a begin. A pair that only ends is said: two bodies that never move don't touch.
  - **Tuning is fields of `Physics`**: `contactStiffness`, `contactDamping`, `contactSpeed`, `bounceSpeed`, `hitSpeed` and `sleeping`, with Box3D's defaults, so a game that writes none steps as it did. `b3t_step` is given them with the gravity, notes them into the stamp every step, and sets the world's before it steps (`b3World_SetContactTuning`, which has no call to read it back, `b3World_SetRestitutionThreshold`, `b3World_SetHitEventThreshold`: numbers of the world's own that every image writes, so calls an image in parts follows). `sleeping` is `b3World_EnableSleeping`, only called when it differs from the world's: not followed, so that tick's image is whole. Turned off, it wakes a world at rest (`roused`), as a gravity that changed does; the other fields step nothing by themselves.
  - **`Hit { other, point, normal, speed }`** is Box3D's hit events, which need `enableHitEvents` on a shape: every shape is made with it. `normal` is from the other body towards the one that hears it (Box3D's is from its shape A to its shape B: `Report` turns it for A's entity). **What it put in the image** is exact, and the only thing here that changed Box3D's own bytes: a bit of each shape's flags, a bit of each contact's, and in each point of a touching contact the speed the two closed at (`normalVelocity`, 0 before): 280 bytes of the pinned match's last 40,812. With that one line taken out, every one of its 300 images is the bytes it was before any of this (`OWN_HASH`, below). It's the same bytes on every SIMD path (the solver writes it a lane at a time, for the lanes that ask), and nothing reads it but the events: the bodies' pin didn't move.

## Collider history and query contexts (2026-10-11)

Physics now exposes current Raycast/Cast/Overlap/Inside as singleton methods. With maxRewind enabled, `Body.rewind` opts whole bodies/parts into match-owned collider history. Native sphere/capsule/box geometry and poses are captured after the physics step. The approved internal tick-completion hook seals final Snap/despawn metadata after queued changes apply; historical frames preserve entity generations. Disabled history avoids capture/bookkeeping and clears old history when disabled after reload. It follows ordinary snapshot, hash, serialization and rollback state.

`physics.Rewind(time, out Query)` produces one detached readonly scene for any number of queries. It validates the requested range and both fractional endpoints, returning false/empty instead of clamping or falling back. Opted-in poses interpolate, Snaps prevent teleport blending, and upper-endpoint geometry/membership is discrete. Other geometry is current, including walls; live bodies opting out use current geometry. Query supports every existing ray, box/sphere/capsule cast and overlap, Inside, and ignore-body cast/ray overloads. Sensors are skipped by rays/casts/overlaps, rays skip starting overlap, and casts report starting overlap at zero with no normal. Native body order and shape-handle ties are preserved. Native geometry helpers validate finite inputs, count bounds and quaternion validity. Returned contexts contain values only and never move bodies, alter contacts or emit events.

Prepared scenes build an immutable preorder BVH; repeated queries use short sorted candidate lists. `rewind` pins readonly hashes, current moving walls, fractional poses, rounded shapes/parts, all shape queries and sensors, queued Snap/despawn endpoints, live opt-out, retained contexts, malformed/stale/missing times, snapshot/pack/unpack/rollback. Release, 1,024 extra colliders and 1,000 rays on this Windows machine: prepare 1.01 ms; historical batch 0.45 ms versus current 0.17 ms (one run; no timing assertion). Updated world/sequence hashes account for schema changes; body results, answer hashes and native resident digests remain unchanged. The new helpers rebind probe point arrays to the returned caller-owned struct before querying.

rewind_network uses the same 28 end-to-end two-client profiles as Box2D, compiled against this package. Player-owned motion changes through sampled input; each shot is compared with the last actual verified view draw command through normal input packing, timestamp validation and rewind. Both hits and misses are checked; accepted hit-point/fraction errors must remain below 0.0001, expired 250 ms history claims must fail, and no profile may resync. The matrix and held-input prediction fix are recorded in notes/netcode.md. These accuracy bounds cover translating axis-aligned boxes; existing tests cover other native shapes/rotations. Real Internet and GPU/display scanout remain outside this deterministic harness.
