singleton_params: 4 systems each tick, 3 stages deep; 2 can run alongside others.
A system starts once everything it runs after is done.

stage 1  Write  (once)
         writes Counter
         alongside nothing
stage 2  ReadOnce  (once)
         reads Counter
         writes Seen
         after Write: it writes Counter, which this reads
         alongside ReadEach
stage 2  ReadEach  (per entity)
         reads Counter
         writes Unit
         after Write: it writes Counter, which this reads
         alongside ReadOnce
stage 3  WriteAgain  (once)
         writes Counter
         after Write: both write Counter (and through ReadOnce)
         after ReadOnce: it reads Counter, which this writes
         after ReadEach: it reads Counter, which this writes
         alongside nothing

Event handlers, at the end of the tick, as their events are sent:
         Spawned: Setup
