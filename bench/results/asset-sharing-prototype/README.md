# Asset sharing ownership experiment (2026-10-11)

The owner requested sharing known asset values, including ordinary values such
as `List<byte>`, until their first write, and required evidence before adopting
the wider container change. This is a scratch ownership experiment, not a
shipped asset-reference or general detach-on-write implementation. Compiler,
engine, user project and installed runtime sources are unchanged by this
experiment. No content comparisons or general deduplication are introduced.

Both variants link the same checkout-built release runtime. The 100-character
game uses exactly the generated source and pack from
[owned-animation-scans](../owned-animation-scans/README.md), which already
includes the previously shipped owned animation validation optimization.
`prototype.ps1` patches only generated byte-list copy/assign/own helpers to
retain an existing packed handle. Model bytes stay immutable in this game;
pose transforms retain their existing ownership. The ordinary byte-list
microbenchmarks use private wrappers around existing runtime functions.
They copy a shared list into owned match storage before editing it.

## Result and gate decision

The corrected cached experiment completed all 36 processes after its own full
quiet window. All 30 corrected simple-experiment rows are retained separately.
The values below are medians of three process means, in milliseconds:

| Native release work | Owned baseline | Shared prototype |
| --- | ---: | ---: |
| 100-character tick | 1.633971 | 0.010648 |
| World hash | 0.879640 | 0.000272 |
| Views + serial palette preparation | 1.625910 | 1.011959 |
| Per-process tick + hash + view sum | 4.139521 | 1.023344 |
| Retain pre-tick snapshot (separate) | 0.022408 | 0.000112 |
| Read-only byte-asset assignment + write interval + cleanup + hash | 0.255297 | 0.000188 |
| Bulk reset to asset + edit + cleanup + hash | 0.256220 | 0.493319 |
| Cold initialization + first edit + cleanup + hash | 0.937519 | 0.942093 |
| Ordinary owned copies + cleanup + hash | 0.005292 | 0.005155 |
| Ordinary cached edits + cleanup + hash | 0.087626 | 0.088710 |

The grid's CPU interval sum is 75.3% lower (4.05x ratio of medians). Before
process means are [3.956779, 4.139521, 4.279325], after [1.023344, 1.020722,
1.027494]; every pair improves, with paired ratios 3.87x/4.06x/4.16x. The
packed native world shrinks from 13,117,656 to 7,256 bytes. Views alone are
37.8% lower: retaining packed model provenance avoids the owned-validation
fallback, beyond the assignment/hash savings. No GPU or FPS gain is claimed.

Ordinary write timing is 0.073837 -> 0.074968 ms, about 1.5% higher; paired
changes are +0.5%/+1.9%/+1.6%. This removes most of the corrected simple
experiment's per-element-check cost (write means before [0.073779, 0.073151,
0.074610], after [0.079314, 0.081535, 0.079833]). Three short processes do not
establish a universal no-regression claim. Owned-copy totals are small and
close; no copy speedup is claimed. Cold first-write total changes vary in sign
across pairs and have essentially the same median; no improvement is claimed.

The bulk reset-and-edit case is 1.93x slower, and slower in every pair. It
releases the old owned lists, assigns references, then allocates detached lists
before the batch flush; pending releases prevent reusing all that space at once.
Packed heap high-water size doubles from 3,146,600 to 6,293,096 bytes, increasing
cleanup and dirty-page hashing. This is not a universal cost for every generated
entity loop, but it is a legitimate workload that the proposed general storage
change must account for. Read-only asset lists remove their payload from the
heap; the corrected first-write-once case returns to the same owned heap/hash
as the baseline once detached.

**Decision:** the ownership experiment supports sharing unchanged animation
and ordinary byte-asset data. It does not pass a blanket rollout gate for
general container storage: the bulk reset-and-edit regression remains, and
the stable-reference/reload/mutation mechanisms below are not implemented or
measured. No production storage change is landed with this evidence. A complete
candidate must preserve value semantics and remeasure these workloads, including
the adverse case; the large read-only win alone is insufficient.

Native and WASI versions pass all six corrected workloads in both variants.
All 12 WASI results agree with native semantic/draw digests and final hashes
within each variant; applicable owned heap sizes also agree. The standalone
container sources compile warning-free with strict C17 flags. The grid retains
100 characters, one mesh command, all three clips (state mask 7), semantic
digest `5991125559186960660` and palette digest `5069683498435541530` in every
valid grid process. `native-checks.json` and `wasi-checks.json` are correctness
runs under concurrent work; their timings are not performance evidence.
`analyze.mjs` verifies all final paired and cross-platform comparisons.
The engine/compiler sources are unchanged, so full production suites were not
rerun for this standalone experiment. Browser/GPU, other native platforms,
sanitizers and CI were not exercised by this experiment.

## Workloads and timing boundaries

The grid harness keeps the pre-tick world, ticks at 60 Hz, hashes the world,
records views and prepares palettes serially. It runs 330 frames, discarding
30 and averaging 300. All three clips are exercised. After timed work, an
accumulated digest reads every character's position, timer, state, selected
index and animation name; another digest covers every integer palette/influence
texture over all frames. Equal digests and work counts verify those outputs.
Raw world hashes differ because representation and allocation differ; they
are not used as a cross-variant equality assertion.

The container cases run 150 rounds, discarding 30 and averaging 120, and keep
one pre-round heap snapshot. Assignment, writing, released-block cleanup and
hashing have separate disjoint timing intervals in the corrected experiment:

- `asset-assign`: repeatedly assign one 16 KiB packed byte asset to 64 lists.
- `first-write`: the same bulk assignment, then edit one byte in every list.
  All 64 assignments and writes happen before one heap flush. This deliberately
  measures a batch reset-and-edit workload; generated per-entity dispatch can
  flush more frequently and its allocation high-water mark can differ.
- `first-write-once`: initialize and first-edit 64 lists in a fresh heap each
  round. Reset/free happens outside measured intervals. This separates cold
  detachment from the repeated reset-and-edit case.
- `mutable-copy`: assign 64 copies of a 256-byte already-owned list.
- `mutable-edit`: edit all 65,536 floats of an already-owned 256 KiB list
  through the writable chunk cache, with a retained snapshot each round.

The corrected mutable-edit fixture constructs a typed float list, and checks
its digest against independent expected values after all 150 rounds. An initial
fixture incorrectly used a byte-list header as a float-list header, overreading
the packed payload in trusted C. The native/WASI disagreement exposed that
mistake. `initial-containers.c` and `initial-rows.json` preserve the failed
experiment for audit; do not run that unsafe fixture or use its mutable-edit
rows as performance evidence. Both variants were corrected and remeasured.

The asset remains byte-identical after every valid process. Each paired case agrees
on the final content digest. Owned controls and cold first-write also agree
on packed heap size and raw heap hash. The microbenchmarks keep their handles
on the C stack, so the shared case's heap-byte count excludes those 64 handles;
the grid's world-byte count includes its component fields.

The corrected simple experiment (`containers-simple.c`, `paired-rows-simple.json`)
checks detachment on every element write and hashes before flushing, with
cleanup outside timed intervals. Its rows are retained as an adverse experiment,
not the final tick-cost comparison. The corrected `containers.c` moves the
detachment check to a writable-cache miss, preserves the existing cache-hit
path, and flushes before hashing as generated ticks do. `measure-simple.ps1`
was adjusted on export to select the preserved `containers-simple-*` binaries;
the original measurement used those binaries under the ordinary names.

Three separate alternating process pairs per case require the named benchmark
gate and a complete 90-second quiet window. Competing build/test/benchmark
processes are checked before and during each measurement. Quiet guards reset
while other checkouts worked; guard-only runs were stopped for the flush
correction and cross-platform checks before measuring any process. Other desktop activity and clocks
are uncontrolled. All valid measured rows are retained, as are the explicitly
invalid initial rows above. Per-process means and their
medians, plus paired ratios, are retained in `summary.json`; these are not
pooled frame medians or confidence intervals.

## Limits

This only measures ownership/copy placement using current physical pack handles.
It does not implement stable asset identity, pack reload, model proof remapping,
match asset-content compatibility, portable world packing, restore/replay,
verified-handle conversion, general nested containers, text, maps, grids or
all generated mutation paths. In particular it must never be adopted by merely
copying these helper edits into the compiler: pack replacement could invalidate
the retained handles, and unmodified byte-list writes could write asset storage.
Those missing mechanisms can have their own cost and must be measured in the
complete implementation. Textures/audio clips already use small asset references.

The grid excludes GPU rendering, networking, session startup and Rooms UI;
it is not an FPS claim. Snapshot timing covers retaining one pre-tick world,
not restoring or replaying several outstanding predictions. Correctness checks
cover the listed outputs, not every observable behavior of a general language
storage change. No production feature is claimed by these measurements.

## Reproduction

Private game source, generated source and assets are not redistributed. With
the identical game/pack already generated in `build/owned-animation/gen`, and
the checkout release engine built with `TIDE_PLATFORM=OFF`:

```powershell
$env:TIDE_HIDDEN = '1'
& ./bench/results/asset-sharing-prototype/prototype.ps1
& ./build/asset-reference-prototype/measure-simple.ps1
Copy-Item build/asset-reference-prototype/paired-rows.json build/asset-reference-prototype/paired-rows-simple.json
& ./build/asset-reference-prototype/measure.ps1
& ./bench/results/asset-sharing-prototype/check-web.ps1
```

The scripts compile only in this checkout and run finite hidden programs.
The native flags are C17, `-O2 -fno-fast-math -ffp-contract=off`, dynamic CRT,
and strict warning flags for the standalone container source. Generated game
compilation uses the same flags as the previous harness. Copy both JSON outputs
here and run `build/node/node.exe bench/results/asset-sharing-prototype/analyze.mjs`
to check equality assertions and recompute the summary. `identities.json`
records measured source, input, library and binary hashes; committed text is
normalized to LF with its exported hashes recorded separately.
